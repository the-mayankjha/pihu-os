# PIHU OS v1.2.9 — MCP Market & Semantic Intent

## Highlights
- Install and update optional MCPs independently from PIHU Market through the PIHU website registry.
- Connections shows installed MCPs and opens package-specific configuration and account sign-in pages after installation.
- MCP cards show author, installed version, tool count, available updates, and package management actions.
- Semantic intent execution replaces command-specific routing: multiple typed tool calls, argument validation, recent execution context, cancellation and execution limits.
- Draft Google documents from instructions or active project source files, review and edit the preview, then create the Google Doc.
- Google Workspace MCP v1.1.2 is available separately in Market, with 30 tools for Gmail, Docs, Drive, Calendar, Tasks, Sheets and Slides. Reconnect Google to grant newly requested permissions.
- Spotify MCP is available separately with PIHU client ID and PKCE sign-in; ordinary users do not enter a client secret.

## Voice and diagnostics
- Live Engine Diagnostics reports real local voice readiness, provider errors, runtime components, and installed MCP state.
- Fixed premature voice watchdog resets that could discard slower command responses.
- Google commands use the installed MCP manager instead of a legacy shell/Python launcher.
- Added email-body decoding for reading messages by subject. Attachment contents are not yet supported.
- Kokoro uses the current development resources and stops its owned process on exit; a parent-process watchdog prevents orphaned services.

## Desktop and packaging
- Spirit companion windows hide horizontal and vertical scrollbars on Windows, Linux and macOS.
- Fixed shared Node license discovery for Windows distribution layouts, with a version-matched official license fallback.
- Release CI uses the shared Node version, disables Finder customization in headless DMG builds, adds AppImage extraction/stripping safeguards, and preserves verbose packaging diagnostics.
- The app includes its voice runtime and four core MCPs: File, System, Project and Web Search. Optional MCPs are downloaded from Market.

## Installation
- macOS: separate Apple Silicon and Intel builds. Ad-hoc signed, not Apple-notarized; macOS may require approval in Privacy & Security.
- Windows: x64 installer.
- Linux: x64 DEB and AppImage. Mark the AppImage executable before opening it.
- Signed updater artifacts are generated by release CI. Installers remain in draft until every platform build and packaged-runtime verification succeeds.

Compilation checks passed during development. Real-account Google automations and the new platform packaging safeguards still require end-to-end validation; a successful release build alone does not verify every account workflow.
