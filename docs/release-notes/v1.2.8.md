# PIHU OS v1.2.8 — Bundled Voice Runtime

This release packages the local voice engine and built-in MCP runtimes with PIHU, so a new device does not need a separate Python installation or first-launch speech-model downloads.

## Highlights
- Bundled portable Python with the required voice and built-in MCP dependencies.
- Included Whisper Small multilingual STT, Kokoro Hindi (`hf_alpha`) and English (`af_bella`) voices, custom wake-word models, OpenWakeWord preprocessing models, and Silero VAD.
- Included the native WhatsApp bridge, Node runtime, and browser/Spotify runtime dependencies.
- Browser automation prefers installed Google Chrome and uses bundled Chromium when Chrome is absent.
- Engine Diagnostics now checks packaged files, speech-model integrity, dependency imports, STT service readiness, both Kokoro pipelines, and wake-word process readiness/errors.
- Fixed eSpeak initialization in relocated or deeply nested installations by keeping phoneme-data paths within the native library's path-length limit.
- Prevented Windows background services and account synchronization from repeatedly opening console windows.
- Release builds use the packaged interpreter and models instead of the legacy first-launch Bash installer or an old user virtual environment.

## Release validation
- Apple Silicon macOS packaging passed strict/deep ad-hoc signature verification and 44 offline checks from inside the app bundle.
- Release CI validates each packaged runtime before publishing: macOS app resources, the installed Windows NSIS payload, and the extracted Linux AppImage. Checks cover native dependencies, model loading, Hindi/English speech synthesis, headless browser launch, and default MCP tool discovery.
- Intel Mac dependencies now build on a native Intel runner.

## Installation and updates
- macOS: separate Apple Silicon and Intel DMG installers. These builds are ad-hoc signed and are not Apple-notarized; macOS may require explicit approval in Privacy & Security. Do not disable Gatekeeper globally.
- Windows: x64 installers.
- Linux: x64 AppImage and DEB packages. For AppImage, mark the downloaded file executable before launching it.
- Signed updater artifacts and `latest.json` are generated by release CI for in-app updates.
- Installers are larger because they now include speech models and runtime dependencies.

Microphone permission still requires OS approval. Cloud AI services and connected accounts require internet access and user credentials. Additional marketplace packages remain on demand. Physical microphone capture and permissions must still be verified on each device.
